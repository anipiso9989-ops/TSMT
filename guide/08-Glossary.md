# Glossary

Use these short definitions as reminders. The chapter references show how each idea works on a problem.

| Term | Meaning |
|---|---|
| Abstraction | Keep the features the reasoning uses and set aside the rest. Ch. 5 |
| Asymptotic reasoning | Compare how quantities grow or shrink at large input sizes. Ch. 22 |
| Auxiliary object | Something you introduce to help an argument, such as a line or an extra variable. Ch. 17 |
| Base rate | How common something is before you use additional information. Ch. 21 |
| Bijection | A pairing where each object on either side has exactly one partner. Ch. 12 |
| Bound | A value a quantity can never go above or never go below under the stated conditions. Chs. 20, 22 |
| Canonical form | A standard description that gives the same result for every representation of the same object. Ch. 14 |
| Certificate | A short piece of evidence someone can check to verify a result, such as a bound paired with a matching example. Ch. 20 |
| Conditional probability | The chance of an event when you restrict attention to cases where another event has occurred. Ch. 21 |
| Conjecture | A precise mathematical claim you suspect is true and have yet to prove. Ch. 31 |
| Constructive proof | A proof of existence that gives an example or a method for building one. Chs. 4, 16 |
| Contrapositive | For “if P, then Q,” the equivalent statement “if Q is false, then P is false.” Ch. 3 |
| Converse | For “if P, then Q,” the statement “if Q, then P.” It requires its own proof. Ch. 3 |
| Counterexample | An allowed case where the claimed conclusion fails. Ch. 32 |
| Decomposition | A division into parts that together account for the original problem. Ch. 14 |
| Descent | A proof that rules out a solution by showing any solution would give a smaller one, even though a smallest one must exist. Ch. 24 |
| Dimensional analysis | Use the units of a quantity to check or constrain a formula. Ch. 27 |
| Double counting | Count the same collection in two ways and equate the totals. Ch. 12 |
| Duality | A verified correspondence that swaps roles, such as rows and columns in a table. Ch. 19 |
| Emergence | A property of a whole system that arises from how its parts interact. Ch. 30 |
| Exchange argument | Improve a candidate by a small swap to show that its original form cannot be optimal. Ch. 20 |
| Expectation | The probability-weighted average of the possible values. Ch. 21 |
| Extremal principle | Choose a smallest or largest case and exploit what that choice forces. Ch. 11 |
| Feedback | An output affects the inputs or state of a later round. Ch. 30 |
| Fermi estimation | Make a rough estimate by breaking a question into smaller estimates you can justify. Ch. 26 |
| Generalization | A claim covering a larger family of cases than the original. Ch. 18 |
| Graph | A collection of vertices joined by edges, used to record connections. Chs. 5, 19 |
| Induction | Prove a starting case, then prove each next case from the current case. Strong induction may use all earlier cases. Ch. 10 |
| Invariant | A value or property that stays unchanged under every allowed move. Ch. 8 |
| Isomorphism | A one-to-one correspondence that preserves the relevant structure in both directions. Ch. 19 |
| Model | A set of assumptions and rules connecting a real question to a calculation. Ch. 25 |
| Modular arithmetic | Reason about integers through their remainders upon division by a fixed positive integer. Chs. 2, 13, 24 |
| Monovariant | A quantity that moves in only one direction under the allowed moves. Strict decrease through nonnegative integers proves termination. Ch. 8 |
| Parity | Whether an integer is even or odd. Chs. 2, 8 |
| Pigeonhole principle | If more objects than boxes are assigned to boxes, some box contains at least two objects. Ch. 13 |
| Probabilistic method | Use a random construction to prove that at least one choice has a desired property. Ch. 21 |
| Relaxation | Loosen constraints to make a problem easier and get a bound for the original. Ch. 20 |
| Sharp bound | A bound that cannot be improved for the stated problem, for example because an allowed case attains it. Chs. 13, 20 |
| Simpson's paradox | A comparison reverses when data groups are pooled, because the group weights can differ. Ch. 29 |
| Symmetry | A transformation that preserves the relevant conditions and goals. Ch. 9 |
| Transfer | Recognize and apply a familiar idea in a different-looking problem. Ch. 24 |
| Transitivity | If A is related to B and B to C, then A is related to C by the same rule. Ch. 1 |
| Validation | Check whether a model describes the real situation well enough for its purpose. Ch. 28 |
| Verification | Check whether an argument or computation follows the stated rules. Ch. 28 |
| Well-defined | The answer stays the same when you choose a different allowed description of the same object. Ch. 2 |
| Without loss of generality | Work on one case after showing how symmetry reduces every other case to it. Ch. 9 |

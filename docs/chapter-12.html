Counting Two Ways: Bijection and Double Counting

1. Core Idea

Two techniques, one idea: the same set can be described in two ways, and both descriptions must give the same count.

  • A bijection is a structure-preserving pairing between two sets. It proves |A|=|B||A| = |B| without counting either, and it often proves an identity by exhibiting the reason it holds.
  • Double counting counts a single set of objects along two different decompositions. The two totals are equal, and that equality is the identity you wanted to prove.

Principle signature. The problem asks for a count, or asks you to prove an identity between combinatorial expressions, or asks to prove existence of an object with a property (a nonzero count proves existence). The presence of binomial coefficients, factorials, sums of products, or "the number of ways" is the giveaway.

Bijections are strictly stronger than algebraic verification: an algebraic proof of a binomial identity confirms it, while a bijective proof explains it and usually generalizes (→ Ch. 18, 23).

2. First Principles

Bijections preserve cardinality. If f:A→Bf : A \to B is injective and surjective, then |A|=|B||A| = |B| (for finite sets). The proof is the definition of counting. The practical content is that a bijection is a reversible encoding: every element of AA has exactly one code in BB, and every code decodes to exactly one element.

Double counting is the same principle applied to a set of pairs. Let R⊆A×BR \subseteq A \times B be a relation. Counting RR by summing over AA gives ∑a|{b:(a,b)∈R}|\sum_{a} |\{b : (a,b) \in R\}|; counting by summing over BB gives ∑b|{a:(a,b)∈R}|\sum_b |\{a : (a,b)\in R\}|. These are equal because both equal |R||R|. The art is choosing RR.

Overcounting is the main hazard. If you count each object kk times, the total is kk times the answer. The discipline: for every object, determine its multiplicity, and prove the multiplicity is constant (or account for the variation). This is where most counting errors occur, and they are usually invisible in the final formula.

Existence from counting. If a count is positive, the object exists. This is the counting route to existence, and it is often easier than construction: "the number of such objects is (nk)>0\binom{n}{k} > 0, hence one exists". The probabilistic method (→ Ch. 21) is the quantitative version of this idea.

Inclusion–exclusion is the correction for overcounting. For sets A1,…,AnA_1,\dots,A_n, |⋃Ai|=∑|Ai|−∑i<j|Ai∩Aj|+∑i<j<k|Ai∩Aj∩Ak|−⋯\left|\bigcup A_i\right| = \sum |A_i| - \sum_{i<j}|A_i \cap A_j| + \sum_{i<j<k}|A_i\cap A_j\cap A_k| - \cdots Each element counted mm times on the right (where mm is the number of sets containing it) is counted (m1)−(m2)+⋯=1\binom{m}{1} - \binom{m}{2} + \cdots = 1 time net. This is double counting applied to the indicator functions.

3. Reasoning Process

  1. Name the set you are counting. Precisely. "The number of ways to choose..." is not precise until you say what counts as the same.
  2. Look for a second description. Can each object be encoded as a binary string, a lattice path, a subset, a pair of subsets, a tiling, a function?
  3. Build the map and prove it is a bijection. Two directions: every object maps to a valid code, and every valid code comes from exactly one object. Both directions are usually short but both are necessary.
  4. For identities, count a set of pairs or triples two ways. Choose the relation RR so that one direction is easy (count by the first coordinate) and the other direction is the expression you want.
  5. Check multiplicities. If you counted with multiplicity, divide by it — and prove it is constant.
  6. Sanity check with small values: n=1,2,3n=1,2,3. A binomial identity that fails at n=2n=2 is wrong, and the check costs ten seconds.

4. Demonstrations

Demonstration 12.1 — A bijection that explains a formula

Claim. ∑k=1n(2k−1)=n2\displaystyle\sum_{k=1}^{n}(2k-1) = n^2.

Bijective proof. Consider an n×nn \times n grid of cells, which has n2n^2 cells. Partition it into "L-shaped shells": the kk-th shell consists of the cells in row kk up to column kk, plus the cells in column kk above row kk — that is, k+(k−1)=2k−1k + (k-1) = 2k-1 cells. The shells for k=1,…,nk=1,\dots,n partition the grid, so the total number of cells is ∑k=1n(2k−1)\sum_{k=1}^n (2k-1), and it is also n2n^2. ◼\blacksquare

What to notice. The algebraic proof (induction) is three lines and explains nothing. The bijection shows why the sum of the first nn odd numbers is a square: the odd numbers are the sizes of the successive shells of a square. This is the kind of understanding that transfers: the same shell decomposition proves that a sum of consecutive odd numbers starting from 11 is a square, and suggests how to handle sums of consecutive integers starting elsewhere.

Demonstration 12.2 — Double counting proves an identity

Claim (Vandermonde). For m,n≥0m,n \ge 0 and k≥0k \ge 0, (m+nk)=∑i=0k(mi)(nk−i).\binom{m+n}{k} = \sum_{i=0}^{k}\binom{m}{i}\binom{n}{k-i}.

Proof. Let AA and BB be disjoint sets with |A|=m|A| = m, |B|=n|B| = n. Count the kk-element subsets of A∪BA \cup B.

First way: directly, (m+nk)\binom{m+n}{k}.

Second way: classify a kk-subset SS by i=|S∩A|i = |S \cap A|. Then |S∩B|=k−i|S \cap B| = k - i, and there are (mi)\binom{m}{i} ways to choose S∩AS\cap A and (nk−i)\binom{n}{k-i} ways to choose S∩BS \cap B. Summing over the possible ii (from 00 to kk, with the convention (ab)=0\binom{a}{b}=0 when b>ab>a or b<0b<0) gives ∑i(mi)(nk−i)\sum_i \binom{m}{i}\binom{n}{k-i}.

Both count the same set, so the totals are equal. ◼\blacksquare

What to notice. The identity is not proved by algebra; it is proved by finding the set that both sides count. This is the general method for binomial identities: ask "what is the set?" before asking "how do I manipulate the symbols?" Also note the role of the convention (ab)=0\binom{a}{b}=0 for out-of-range bb: it makes the sum range irrelevant, which is a small but essential piece of bookkeeping.

Demonstration 12.3 — Double counting a set of incidences

Claim (handshake lemma). In any finite graph, ∑v∈Vdeg(v)=2|E|\displaystyle\sum_{v \in V}\deg(v) = 2|E|.

Proof. Let R={(v,e):v∈V,e∈E,v is an endpoint of e}R = \{(v,e) : v \in V,\ e \in E,\ v \text{ is an endpoint of } e\}.

Count by vertices: for each vv, there are deg(v)\deg(v) edges incident to it, so |R|=∑vdeg(v)|R| = \sum_v \deg(v).

Count by edges: each edge has exactly two endpoints, so |R|=2|E||R| = 2|E|.

Hence ∑vdeg(v)=2|E|\sum_v \deg(v) = 2|E|. ◼\blacksquare

What to notice. The set RR is a set of incidences, not of vertices or edges. Choosing the right relation is the whole trick, and it is a general recipe: when two quantities should be equal, look for a set of pairs that each side counts naturally. The corollary — the number of odd-degree vertices is even — follows immediately, and gives a second proof of Demonstration 10.3.

Demonstration 12.4 — A bijection between two apparently unrelated families

Claim. The number of compositions of nn into parts 11 and 22 equals Fn+1F_{n+1}, where F1=F2=1F_1 = F_2 = 1.

Bijection. A composition of nn into 11s and 22s corresponds to a tiling of a 1×n1 \times n strip by monominoes (length 11) and dominoes (length 22): read the parts left to right and place tiles of those lengths. The correspondence is clearly reversible.

Now let ana_n be the number of such tilings. Consider the leftmost tile: it is either a monomino (leaving a strip of length n−1n-1) or a domino (leaving a strip of length n−2n-2). Hence an=an−1+an−2,a1=1,a2=2.a_n = a_{n-1} + a_{n-2}, \qquad a_1 = 1,\ a_2 = 2. This is the Fibonacci recurrence with a1=F2a_1 = F_2, a2=F3a_2 = F_3, so by induction an=Fn+1a_n = F_{n+1}. ◼\blacksquare

What to notice. The bijection converted a question about arithmetic decompositions into a question about geometric objects, and the geometric objects have an obvious recursive structure (look at the leftmost tile). This is a change of representation (→ Ch. 15) implemented by a bijection, and it is why tilings, compositions, and Fibonacci numbers are the same subject.

5. Connections

  • ← Ch. 5. A bijection is an isomorphism of sets-with-structure; the "structure" preserved is the combinatorial decomposition.
  • ← Ch. 10. Recursive counting produces recurrences; induction proves the closed form.
  • → Ch. 13. Pigeonhole is counting applied to a partition; the two chapters are the same tool used for different conclusions.
  • → Ch. 14. Canonical forms are what make bijections work: you need a unique representative to have a well-defined inverse.
  • → Ch. 15. Generating functions are the algebraic shadow of a bijection; the coefficient counts the objects.
  • → Ch. 21. The probabilistic method converts a counting bound into an existence statement.

6. Limitations

Bijections are hard to find and easy to get wrong. The inverse direction is where errors hide: a map that is injective but not surjective gives an inequality, not an equality. Always check both directions, and check the boundary cases (n=0n=0, empty set).

Not every identity has a natural bijective proof. Some binomial identities are most easily proved by generating functions or by algebra. Insisting on a bijection can waste time; the bijection is preferable when found, not mandatory.

Double counting requires a well-defined multiplicity. If objects are counted with varying multiplicity, the naive double count is wrong. The repair is to count a weighted set or to restrict to a canonical representative.

Counting does not produce the objects. A count proves existence (if positive) but gives no construction. For algorithmic purposes you need an unranking procedure, which is a separate problem.

Asymptotics need more than exact counts. Exact formulas can be useless for large nn; you need estimates (→ Ch. 22).

7. Applications

  • Algorithm analysis. Counting the number of operations of an algorithm is double counting over loop iterations; the analysis of sorting networks and hash tables is combinatorial counting.
  • Statistical mechanics. Counting microstates is the definition of entropy; the combinatorics of configurations determines thermodynamic quantities.
  • Information theory. Counting codewords and error patterns gives the sphere-packing bound; the entire subject is combinatorial counting with a metric.
  • Population genetics. Counting genotypes and allele configurations under Mendelian inheritance is a bijection problem.
  • Computer science. Unranking (mapping an index to the kk-th object) is the inverse bijection, used in random sampling and combinatorial testing.
  • Finance. Counting paths in a binomial tree (and their probabilities) is the combinatorial core of option pricing.

8. Mastery Criteria

You have this chapter when you can:

  1. Given a combinatorial identity, identify the set that both sides count, or explain why no such set is apparent.
  2. Construct a bijection and verify both directions explicitly.
  3. Choose the right relation for a double count, and prove the multiplicity is uniform.
  4. Use inclusion–exclusion correctly, including the sign pattern and the truncation.
  5. Use a positive count to prove existence, and say what the count does and does not deliver.
  6. Sanity-check any counting formula on small cases before trusting it.

Diagnostic question. "Prove this identity." A learner who reaches for algebra first is not yet thinking combinatorially. A learner who asks "what does each side count?" has the principle.

AI Tutor Brief

  • Generate: (i) identities with a clean bijective proof and identities that resist one; (ii) double-counting problems where the relation must be discovered; (iii) overcounting traps (circular arrangements, identical objects, symmetry); (iv) existence-by-counting problems; (v) inclusion–exclusion problems with a twist (at least one, exactly one, none).
  • Probe misconceptions: treating "number of ways" as unambiguous; forgetting to divide by multiplicity; assuming a map is a bijection because it is injective; sign errors in inclusion–exclusion.
  • Transfer distance: medium-high. Combinatorial reasoning is highly transferable; vary the objects (sets, graphs, strings, paths, partitions).
  • Do not accept an algebraic verification when the task explicitly asks for a combinatorial proof. When the task says only "prove", accept either — but ask the learner which one explains why the identity holds.
